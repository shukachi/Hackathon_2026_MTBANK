Схема работы модели и логика предлагаемого решения (п.6 ТЗ: «Product Canvas: схема работы модели и логика предлагаемого решения»). Структура — по `plan.md`, раздел 1.2.

## 1. Problem / Jobs-to-be-done

Общая формулировка проблемы (слайд 2 презентации банка): семье нужен удобный способ управлять повседневными расходами ребёнка, сохраняя баланс между контролем и самостоятельностью.

| Сегмент | Jobs-to-be-done |
|---|---|
| Родитель | Предоставлять ребёнку деньги на ежедневные расходы без наличных; понимать, как и на что они расходуются; управлять доступными суммами и ограничениями; быть уверенным, что ребёнок не попадёт в опасную или мошенническую ситуацию. |
| Ребёнок 7–13 лет | Иметь свою карту «как у взрослых»; получить удобный доступ к деньгам, которые дал родитель; самостоятельно оплачивать повседневные покупки; постепенно учиться распоряжаться средствами, не боясь ошибиться (ошибка обратима — родитель видит и может скорректировать). |
| Подросток 14–17 лет | Получить больше свободы в тратах, включая онлайн-покупки и подписки; совершать операции самостоятельно без постоянного согласования с родителем по каждой мелочи; подготовиться к статусу полноценного взрослого клиента банка. |

| Сегмент | Описание | Оценочный размер рынка (РБ) |
|---|---|---|
| Семьи с детьми 7–13 лет, уже являющиеся клиентами Moby | Родитель — активный пользователь мобильного банка, ищет инструмент для карманных денег без наличных | Оценка: около 150–250 тыс. семей потенциально адресуемы в клиентской базе банка |

## 3. Value Proposition

| Сегмент | Ценностное предложение |
|---|---|
| Родитель | Полный контроль и прозрачность расходов ребёнка в привычном приложении Moby, без нового логина и нового интерфейса; лимиты, запрет категорий, подтверждение операций и блокировка карты — за секунды, в том числе голосом/текстом через AI-команду. |
| Ребёнок 7–13 лет | Собственная карта и ограниченная самостоятельность; квесты и цели накопления превращают управление деньгами в игру, а не в обязанность. |
| Подросток 14–17 лет | Реальная финансовая автономия в рамках согласованных лимитов + механизм самостоятельно запросить больше прав, когда он к этому готов — без необходимости «просить денег каждый раз». |
| Банк | Новый финансово-активный сегмент клиентов (дети и подростки) с перспективой перехода во взрослую клиентскую базу после 18 лет, дополнительный оборот и остатки по счетам семьи, кросс-продажи доп.продуктов внутри одного Family-профиля. |

## 4. Схема потока (логика решения)

### 4.1 Основной цикл: онбординг → операция → лимит → подтверждение

```
[Родитель]
   │ 1. Узнаёт о пакете в Moby (описание условий, точка входа)
   ▼
[Оформление пакета]
   │ 2. Выбирает возраст ребёнка: 7–13 ИЛИ 14–17
   │ 3. Даёт согласия (чекбокс + фиксация даты/времени, см. legal-notes.md)
   ▼
[Core banking: создание Family-профиля]
   │ 4. Создаётся профиль ребёнка внутри семьи родителя
   │ 5. Выпускается карта ребёнка (физическая / физическая+цифровая для подростка)
   │ 6. Ребёнку присваивается собственный логин + временный пароль (передаёт родитель)
   ▼
[Ребёнок входит в Moby в ограниченном режиме]
   │ 7. Логинится под своими учётными данными
   │ 8. Видит баланс, карту, доступные в рамках прав функции
   ▼
[Ребёнок совершает операцию] (оплата картой / симуляция покупки в демо)
   │ 9. Core banking проверяет: категория (MCC) разрешена? Лимит по периоду не превышен?
   ├─── Лимит/категория OK ──────────────► операция проходит, баланс и прогресс обновляются
   │
   └─── Требуется подтверждение ИЛИ лимит превышен
          │ 10. Push-уведомление родителю с деталями операции
          ▼
     [Родитель]
          │ 11. Подтверждает ИЛИ отклоняет операцию
          │ 12. При необходимости сразу меняет лимит/правило на будущее
          ▼
     Решение применяется, ребёнок видит результат (разрешено/отклонено)
   ▲
   └──────────────── цикл замкнут: следующая операция снова проходит проверку ──┘
```

### 4.2 Ветка access-request: запрос расширения прав

```
[Ребёнок / Подросток]
   │ 1. В интерфейсе видит функцию/продукт, к которому нет доступа
   │    (например: подписка, партнёрская скидка, накопительный продукт)
   │ 2. Нажимает «Запросить доступ» → формирует access-request
   ▼
[Уведомление родителю]
   │ 3. Родитель получает push/уведомление в Moby с описанием запроса
   ▼
[Родитель принимает решение]
   │ 4a. Approve → право применяется немедленно, функция открывается ребёнку
   │ 4b. Deny → ребёнку приходит явный отказ (без права повторного автоматического запроса в тот же день — защита от спама запросами)
   ▼
[Ребёнок видит статус запроса и, если approve, пользуется новой функцией]
```

### 4.3 Ветка геймификации

```
[Квест/урок финансовой грамотности создаётся родителем или системой по умолчанию]
   │ 1. Ребёнок открывает задание (QuestsPage)
   │ 2. Выполняет (проходит урок / достигает цели накопления)
   │ 3. Система начисляет баллы — отдельно от баллов родителя
   │ 4. Родитель видит прогресс ребёнка в своём дашборде (QuestsManagePage)
   └── Цикл повторяется: новые квесты открываются по мере роста ребёнка
```

## 5. Состав пакета (наполнение, п.4.1 ТЗ)

| Категория | Состав | Возрастная специфика |
|---|---|---|
| Платёжный инструмент | Физическая карта (детский дизайн) / физическая + цифровая карта с онлайн-покупками | 7–13: только физическая; 14–17: + цифровая карта и онлайн-операции |
| Дополнительные финансовые сервисы | «Карманные деньги» (регулярные переводы от родителя), цель накопления, накопительный продукт для долгосрочных целей, страхование ребёнка | Накопительный продукт и страхование доступны с момента выпуска пакета; заявка на накопительный продукт для подростка может инициироваться им самим через access-request |
| Нефинансовые сервисы | Подписки, скидки у партнёров, образовательный контент для детей и родителей | Подписки доступны преимущественно подросткам 14–17 по умолчанию, детям 7–13 — через access-request |
| Спецусловия для семьи | Особые условия на обслуживание и продукты для одной семьи (пакетные тарифы, сниженные комиссии) | Общие для всей семьи, не зависят от возраста конкретного ребёнка |
| Управление родителем | Выпуск продуктов и функций ребёнка, лимиты на траты, запрет категорий, подтверждение операций, блокировка карты | Набор доступных ограничений шире для 7–13 (всё по умолчанию под подтверждением), уже — для подростка (по умолчанию самостоятельность в рамках лимита) |
| Геймификация | Задания от родителей, обучение финансовой грамотности, награды за достижения и цели накопления, прогресс виден родителю | Контент заданий и форма наград различаются по возрастной группе |
| Безопасность | Запрет операций в азартных играх и категориях 18+, защита от мошенников, защита персональных данных ребёнка, понятный порядок действий при потере карты и спорных операциях | Единые требования для обеих возрастных групп |

## 6. Control & Safety layer

- **Лимиты** — по сумме и периоду (день/неделя/месяц), опционально по категории трат (например, «сладости», «игры», «подписки»).
- **Запрет категорий** — технически через MCC-коды в `limits_engine`: жёсткий запрет 18+/азартных игр независимо от настроек родителя; остальные категории родитель может разрешать/запрещать выборочно.
- **Подтверждение операций** — настраиваемый родителем режим (по умолчанию для 7–13, по превышению лимита — для 14–17).
- **Блокировка карты** — мгновенная, в один шаг, доступна родителю в любой момент (потеря карты, подозрение на мошенничество).
- **Access control на уровне данных** — родитель видит и управляет только своей семьёй; операции с чужим `family_id` отклоняются на уровне backend (`get_current_parent`), что также является механизмом защиты персональных данных ребёнка.

Подробнее о юридических рамках этого слоя — `docs/legal-notes.md`.

## 7. Revenue streams / Cost structure

Полная модель расчёта, допущения и итоговая таблица — в `docs/economics.md`. Краткая логика:

- **Доходы банка на семью:** оборот по картам (interchange), доход от остатков на счетах/депозитах семьи, партнёрские выплаты, маржа от кросс-продажи доп. продуктов (накопительный счёт, страхование).
- **Расходы банка на семью:** амортизация CAC на привлечение семьи, бонусы/кешбэк по программе лояльности, минимальные операционные расходы (фича реализована внутри существующего Moby, не отдельная инфраструктура).
- Итоговый срок окупаемости и чувствительность к ключевым допущениям — см. таблицу и абзац чувствительности в `economics.md`.

## 8. Key metrics

| Метрика | Что показывает |
|---|---|
| Активные Family-профили | Число семей, реально использующих пакет (не только оформивших) |
| Оборот по детским картам (BYN/мес) | Прямой вклад в комиссионный доход банка |
| % выполненных квестов от назначенных | Вовлечённость ребёнка, эффективность геймификации |
| Retention родителей (месяц к месяцу) | Устойчивость продукта как привычки семьи, а не разовой активации |
| Конверсия «ребёнок → взрослый клиент» (после 18 лет) | Долгосрочная ценность для банка — ключевой нефинансовый LTV-аргумент |
| Доля access-request, одобренных родителем | Индикатор баланса «контроль vs самостоятельность» — слишком низкая доля может говорить о завышенных по умолчанию ограничениях |
